# NCIT Website: Content & Customisation Guide

How to add the logo, photos and real content to the Phase 0 pages, and which file controls what.

> Phase 0 pages are static HTML. You edit text directly in the files listed below. From Phase 2 onwards, most of this content (banners, news, notices, events, leadership messages, department pages) moves into the dashboard, where admins and HODs edit it without touching code.

---

## 1. The golden rule: edit `src/`, then build

```
frontend/
├── src/
│   ├── pages/            ← EDIT HERE: page content
│   │   ├── index.html                Home page
│   │   ├── department.html           Template for every /departments/<name> page (content comes from the dashboard)
│   │   └── dashboard/index.html      Dashboard (Users & access)
│   ├── partials/         ← EDIT HERE: parts shared by every public page
│   │   ├── head.html                 <head> tags (fonts, CSS, favicon)
│   │   ├── preview-notice.html       Yellow "Design preview" strip
│   │   ├── logo.html                 Emblem + college name in the header
│   │   ├── header.html               Top bar, main menu, mega-menus, mobile menu, search
│   │   └── footer.html               Footer: address, links, copyright
│   └── css/site.css      ← Brand colours, fonts, component styles
│
├── public/               ← GENERATED by `npm run build`. Don't edit pages here.
│   ├── index.html, department.html, dashboard/index.html
│   └── assets/
│       ├── img/ncit-logo.png        ← PUT THE LOGO HERE
│       ├── img/photos/*.jpg         ← PUT PHOTOS HERE
│       ├── img/favicon.svg          Browser-tab icon
│       ├── img/icons.svg            Icon set (Lucide)
│       ├── js/site.js               Menus, carousel, tabs, drawers
│       ├── js/dashboard.js          Dashboard sample data and behaviour
│       ├── css/site.css             Compiled CSS (generated)
│       └── fonts/                   Self-hosted fonts
└── scripts/build-pages.mjs  Joins partials into pages
```

> **Common mistake:** editing `frontend/public/index.html` or `public/department.html` directly. Those are rebuilt from `src/` and your changes vanish on the next `npm run build`. Always make text changes in `src/pages/` or `src/partials/`.

**Workflow**

```bash
cd frontend
# 1. edit files in src/pages or src/partials
npm run build                          # 2. rebuild public/
python3 -m http.server 5173 -d public  # 3. preview at http://localhost:5173
```

- `npm run build` overwrites `public/index.html`, `public/department.html` and `public/dashboard/index.html`. Anything you type directly into those three files is lost on the next build.
- Images, JS and fonts in `public/assets/` are **not** generated. Add and edit them in place.
- The header and footer exist **once**, in `src/partials/`. Change them there and every page updates on build.
- In `src/pages/*.html`, lines like `<!-- @include header -->` pull in a partial. Leave them as they are.

If `npm run build` fails with `tailwindcss: command not found`, run `npm install --include=dev` inside `frontend/` first.

**Finding things:** line numbers move as you edit, so this guide gives text to search for (Ctrl+F) in each file. Approximate line numbers are given as hints.

## 2. Logo

| What | File | Action |
|---|---|---|
| Header emblem (all public pages) | `public/assets/img/ncit-logo.png` | Save the official emblem here: transparent PNG, square-ish, at least 256 × 256 px. Nothing else to change; the "NCIT" badge disappears automatically once the file exists. |
| College name next to the emblem | `src/partials/logo.html` | Text "Nepal College of" / "Information Technology". It is hidden on phones (under 640 px) because the emblem already contains the name. |
| Dashboard sidebar | `src/pages/dashboard/index.html` | Uses the same `ncit-logo.png`; nothing to change. |
| Browser-tab icon | `public/assets/img/favicon.svg` | Replace with a small square version of the emblem. For a PNG, save `favicon.png` and change the `<link rel="icon" …>` line in `src/partials/head.html` to `href="/assets/img/favicon.png" type="image/png"`. |

If you use SVG or another file name, change the `src` in `src/partials/logo.html` (`<img src="/assets/img/ncit-logo.png" …>`) to match.

## 3. Brand colours

All colours live in **one place**: the `@theme { … }` block near the top of `src/css/site.css`. They were estimated from the logo image; replace them with the official values.

| Token | Current | Used for |
|---|---|---|
| `--color-brand-800` | `#182c85` | **Main royal blue**: primary buttons, apply band, links |
| `--color-brand-950` / `-900` | `#0a1440` / `#101f5c` | Top bar, footer, dashboard sidebar (darkest blues) |
| `--color-brand-700` / `-600` | `#2140a6` / `#2d53c4` | Links, hover states, focus outline |
| `--color-brand-200` / `-100` / `-50` | light blues | Text on dark backgrounds, photo placeholders, tags |
| `--color-om-600` / `-700` | `#cf1f29` / `#a8131c` | **Red**: Apply buttons, urgent notices |
| `--color-sky-500` / `-300` | `#2f97d3` / `#8fcdef` | Accents on dark backgrounds |

Keep the dark-to-light order (950 darkest, 50 lightest) so text stays readable. Run `npm run build` afterwards.

Also update `<meta name="theme-color" content="#101f5c">` in `src/partials/head.html` (the mobile browser bar colour).

## 4. Photos

Every photo position is a **named slot**. Save a photo with the exact file name in `frontend/public/assets/img/photos/` and it appears on refresh, with no code change and no rebuild. Until then a light-blue placeholder labelled "Photo to come" shows.

**Format:** JPEG with a **lowercase** `.jpg` extension, exactly as named below. Your Mac treats `photo.JPG` and `photo.jpg` as the same file, but the Linux web server does not, so a wrong case shows a placeholder only after the site goes live. Convert PNGs to JPEG and rename them. Resize to about the minimum width listed and keep each file under about 500 KB (squoosh.app or tinypng.com); camera originals of 10 MB make the home page very slow on phones.

| File name | Where | Shape | Min. width |
|---|---|---|---|
| `hero-campus.jpg` | Home banner, slide 1 | Landscape 16:9 | 2000 px |
| `hero-admissions.jpg` | Home banner, slide 2 | Landscape 16:9 | 2000 px |
| `hero-techfest.jpg` | Home banner, slide 3 | Landscape 16:9 | 2000 px |
| `lab-students.jpg` | Academics mega-menu (desktop) | Portrait 4:5 | 600 px |
| `news-robotics.jpg` | Home → News, large story | Landscape 16:10 | 1400 px |
| `news-convocation.jpg`, `news-mou.jpg`, `news-lab.jpg` | Home → News, small stories | Square | 400 px |
| `executive-director.jpg` | Home → Leadership (large) | Portrait 4:5 | 600 px |
| `director.jpg`, `principal.jpg` | Home → Leadership (small) | Portrait 4:5 | 300 px |
| `campus-library.jpg` | Home → Campus life, large | Landscape 4:3 | 1400 px |
| `campus-lab.jpg`, `campus-sports.jpg` | Home → Campus life, small | Landscape 16:9 | 900 px |
| `alumni-1.jpg` … `alumni-4.jpg` | Home → Alumni | Portrait 4:5 | 600 px |

Department page photos (department, HOD, faculty, labs, students) are uploaded in the dashboard; see `DEPARTMENTS.md`.

Photos are cropped to fill their frame, so keep faces near the centre. For the banner photos, keep the bottom-left area calm; the headline sits there over a dark fade.

**Alt text:** every `<img>` has an `alt="…"` describing the photo. When you change a photo, update its alt text to describe the real picture (for example "Students in the NCIT computer lab"). Decorative thumbnails use `alt=""`.

**Placeholder labels** (`<span class="photo-label">Photo to come…</span>`) hide automatically when the photo loads. You can delete them once all photos are in.

## 5. Remove "preview" and "Sample" markers

Every invented item carries an amber **Sample** tag: `<span class="sample">Sample</span>`.

1. Replace the content with real content (sections 6–9).
2. Delete the `<span class="sample">Sample</span>` next to it.
3. Search all files for `class="sample"` to find what's left.

When nothing is left, remove the yellow "Design preview" strip: in `src/partials/header.html`, delete the line `<!-- @include preview-notice -->` (line 3).

The matching HTML in `index.html` is only a fallback shown if the content service is down. The rows below for those sections apply to that fallback only.

Sections in order. Everything marked **Sample** must be replaced.

| # | Section | Search for | What to change |
|---|---|---|---|
| — | Browser title and Google description | `<title>` (line 5), `meta name="description"` (line 6) | Title and 150-character summary shown in search results |
| 1 | **Banner carousel** (3 slides) | `<article class="slide` (lines ~17, 35, 53) | Per slide: photo (section 4), headline (`<h1>` on slide 1, `<h2>` on the others), sentence below it, button labels and links. Slides 2–3 contain sample dates. To add a slide, copy a whole `<article class="slide …">…</article>`, then add a matching `<button … data-goto="3" …>` in the controls below and update the `aria-label="1 of 3"` counts. To change the speed, edit `data-interval="7000"` (milliseconds). |
| 2 | **Quick links** row | `aria-label="Quick links"` | 6 links. Replace `href="#"` with real pages. |
| 3 | **About in brief** | `Technology education, close` | Heading, two paragraphs, and the fact list (`<dl>` around line 112): Established, Affiliation, Campus, Programmes, Recognition. **Confirm the programme count and recognition line with the college.** |
| 4 | **Departments & programmes** | `id="departments"` | Filled automatically from the published departments. The list in the HTML is only a fallback if the service is down. |
| 5 | **News** | `id="news-title"` | 1 large + 3 small stories: photo, tag, date (both the visible text and the `datetime="YYYY-MM-DD"`), headline, summary, link. |
| 6 | **Upcoming events** | `id="events"` | Filled automatically with the next 4 published events (Phase 4). Add events in the dashboard → **Events**; see [EVENTS-AND-CLUBS.md](EVENTS-AND-CLUBS.md). The events in the HTML are only a fallback. |
| 7 | **Notices** | `id="notices"` | 4 notices: category tag (`tag-om` = red for Exam, plain `tag` = blue for Admission, `tag-leaf` = green for Holiday, `tag-amber` = amber for Result), date, title, link to the PDF. |
| 8 | **Messages from our leadership** | `id="leaders-title"` | Executive Director (large quote), Director and Principal (small): **real names**, a short quote from each message, link to the full message. Portrait photos per section 4. |
| 9 | **Campus life** | `id="campus-title"` | 3 photos; Facilities list (6 items, confirm with the college); ECA & clubs (paragraph + club buttons). The club buttons are filled automatically from the published clubs (Phase 4; dashboard → **Clubs**). |

## 8. Department pages

Department pages are no longer edited in HTML. Each Head of Department (or a Super Admin) edits them in the dashboard under **My department** / **Departments**. See [`DEPARTMENTS.md`](DEPARTMENTS.md).

- Addresses: `/departments/computer`, `/departments/it`, `/departments/civil` … (one template for all of them: `src/pages/department.html` + `public/assets/js/department.js`).
- Photos for department pages are uploaded in the dashboard, not placed in `assets/img/photos/`.
- The home page department list fills itself from the published departments.

## 11. Common edits: quick recipes

**Change a headline or paragraph:** find the text in `src/pages/…` or `src/partials/…`, edit it between the tags, then `npm run build`.

**Change a link:** edit the `href="…"`. Use `/page.html` for this site, `https://…` for other sites, and `#section-id` to jump within the page.

**Add a notice:** in `src/pages/index.html`, copy one `<li class="group relative flex items-start gap-4 py-5">…</li>` inside `id="notices"`, paste it at the top of the list, and change the tag, date and title. Point the link to the PDF, saved in e.g. `public/assets/docs/` (create the folder).

**Add an event:** not in the HTML any more. Use the dashboard → **Events** (Event Admin or Super Admin).

**Characters:** write `&amp;` for `&` inside HTML text (e.g. `News &amp; events`). Nepali text works as-is; the files are UTF-8.
